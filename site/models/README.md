# models/ — the bundled translator's weights (NOT committed, NOT a build input)

This directory is served by `serve.ts` at **`/models/<file>`** with byte ranges
(`accept-ranges: bytes`, honest `206` responses, `416` + `bytes */size` when a range
cannot be satisfied). `src/game/translate/model-manifest.ts` is the single source of
truth for which file is expected, how big it must be, and what it must hash to.

**Nothing heavy in this directory is committed.** `.gitignore` ignores `/models/*`
(except this README) and `*.bin` / `*.onnx` / `*.gguf` / `*.safetensors` outright.
It is also outside `dist/client` on purpose: anything in `public/` is copied into the
build output and enters the build id (`serve.ts` fingerprints the name + size of
every file there), so a model in `public/` would make every deploy a full
re-download for every player.

## What is here right now

| file | what it is | size | pinned sha256 |
| --- | --- | --- | --- |
| `pipeline-probe-v1.bin` | the deterministic stand-in the pipeline is proved against | 20,000,000 B | in the manifest |

The probe can be regenerated byte-for-byte at any time:

```sh
cd site && bun run scripts/probe-weights.ts 20000000 models
```

Same seed, same size → same bytes → the sha256 in the manifest still holds. It is
real content (a hash chain), not zeros, so a truncated or reordered transfer fails
verification instead of passing as a plausible blob.

## Flipping the real 603 MB model on

1. Put the real file here under the name the manifest expects
   (`m2m100_418m-v1.onnx` — `MODEL_PROFILES.m2m100.file`). It is gitignored, so it
   stays a runtime asset.
2. Pin its hash: `cd site && bun run scripts/verify-weights.ts` prints the served
   file's real size + sha256 and tells you whether the manifest agrees. Paste the
   hash into `MODEL_PROFILES.m2m100.sha256`.
3. Change `ACTIVE_MODEL_ID` in `src/game/translate/model-manifest.ts` to `"m2m100"`.
4. Add the inference runtime in `src/game/translate/runtime/engine.ts` (its header
   lists the three steps). Nothing else changes: the loader, the cache survival
   across publishes, the progress UI and the engine seam are already in place and
   gated by `translate-tests`.

## Bandwidth, honestly

Every player downloads these bytes **once per model version** — the cache bucket
`dse-model-v1` is on the service worker's keep-list, so a publish does not evict it
and an update re-downloads nothing. The cost is therefore
`players × model size`, served from this box (same origin), plus the store's own
distribution if the app is ever shipped with the weights inside it. `translate-tests`
prints the measured byte total for whatever profile is active; the 603 MB figure is
the model's own size, not a guess.
